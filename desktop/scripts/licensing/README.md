# 续舟发行许可检查

`node scripts/licensing/verify.cjs --notices-only` 只检查随附声明的完整性和文件校验值；成功不表示可以发行。

`node scripts/licensing/verify.cjs --for-build` 核对构建候选的完整声明、程序、资源、运行依赖和桥接模块引用。beforePack 使用这个检查；候选通过只允许生成安装包，尚不表示最终发行核验通过。普通 `bun run package` 编译桌面代码，应用启动不经过发行门禁。

`node scripts/licensing/verify.cjs --artifact-report <报告路径>` 在完整构建检查后验证该安装包的最终报告。报告绑定候选策略、实际安装文件、安装包、源码包及功能证据的校验值；改状态字段不能批准不同的程序。安装包不能包含自身的最终哈希，因此内置策略保留 candidate，最终结果放在包外的 `release-verified.json`。

对已有完整发行目录，可使用 `node scripts/licensing/artifact.cjs <release-verified.json路径>` 只读复验安装包、实际安装文件、源码及证据，验证不需要登录外部 AI。发行目录也附带同一验证器的副本。

本机开发版中原来的 Core 包含受限 PDF 材料，旧策略继续阻断它。发行构建从源码移除了整个受限技能，加入独立替代文件并重新编译；不能靠删外部文件或改文案批准旧二进制。Windows 候选使用固定 Node、四个固定来源的 Hub 扩展及纯 JavaScript 连接依赖，实际包会逐版本匹配许可清单。原生 sharp/libvips、canvas 及未审查的原生 Node 模块被拦截。不得把动态拉取的 dist-latest 自动视为已审核。

升级依赖、修改声明或改变打包范围后必须重新生成审查结果。标准许可条款补充与实际上游原文分开标记；未知或禁止分发的内容不能因有一个通用 LICENSE 文件就被放行。

核心验证保留首次完整工作区的原始退出码和日志。经核实只涉及 Windows 测试环境及测试文件的失败，可以在确认生产 Rust 未改动后复跑相关完整测试组；门禁逐一核对原失败案例确实重跑成功，遇到未知失败继续阻断。最终报告明确记录这种复验方式，不把首次失败写成首次通过，也不重复累计通过数。

2026-10-16 发行候选另含一项已定位的 Windows 目录链接删除修复，具体修改及源文件校验值记录在 Core sourceReview 中。该候选必须重新完成全工作区测试，并将结果绑定实际 Rust 源文件与 Cargo.lock；历史失败及旧安装包保存在构建快照中。实际安装后的 Core 还通过 HTTP 技能导入接口验证失效链接可恢复、有效链接的源文件不受影响。未知失败、未完整执行或源码变化均继续阻断最终批准。
