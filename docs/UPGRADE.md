# 聊天保护、升级和回退

Beta 与现用版并存：安装目录、快捷方式、卸载注册项、默认聊天目录和配置指针分别使用 XuzhouBeta 通道。Beta 不自动打开原版的配置指针，也不迁入旧工作台配置或接管 aionui 链接。

原版的历史聊天仍由原版保留。Beta 的 Codex 本地列表读取用户本机的原生项目和对话；这不等于已把全部续舟聊天与附件迁入 Beta。

## Beta 内升级

1. 结束回复、文件操作和备份任务，退出将被更新的 Beta。
2. 先自行保留一份聊天资料与项目附件的副本。默认聊天目录为 AppData/Roaming/XuzhouBeta；显式指定的目录以用户自己的配置为准。
3. 将新版安装到原 Beta 安装目录。程序仍运行时，安装器应拒绝覆盖，未通过此检查不要继续。
4. 启动后核对旧消息、附件、暂停设置与同步回执。版本回退也应先在副本验证。

不要让两个版本同时使用同一个聊天目录。XUZHOU_PROFILE_DIR 可显式覆盖目录，使用者应先确认路径并关闭占用它的程序。对私人资料的迁移不能用未经退出确认的数据库文件复制代替一致性备份。

## 本版验收方法

发行验证只在独立测试目录内创建合成的旧聊天、消息、附件和同步记录。先用已核对的 2.3.0 程序打开，再由最终 Beta 安装包使用同一份测试聊天副本，核对内容并重启；回退仅在该测试副本执行。Beta 安装器会拒绝覆盖不带 Beta 标记的非空旧安装目录。具体通过项目与最终文件校验值见 verification/upgrade.json。

这不表示已在用户私人聊天上执行覆盖升级。Core 与 SQL 迁移沿用原已审查二进制，未重新编译或替换为其他版本。

卸载只清理安装包列出的程序文件，不主动删除聊天目录或用户后来添加的文件。若需彻底删除私人资料，应另行自行管理并核对原生客户端、项目附件和外部备份中的副本。
