# GitHub 公开测试版发布步骤

发行材料核验通过后，只使用干净源码目录和对应的发行附件。不要上传私人开发目录、证据日志、运行配置、数据库、屏幕截图、旧聊天或源目录的 Git 历史。

1. 核对 release-verified.json、SHA256SUMS.txt 和 verification 中的最终校验结果。版本必须统一为 2.3.1-beta.2。
2. 使用现有公开仓库 seanyeagerx-svg/xuzhou，在独立发布检出中更新干净源码，保留既有公开历史、LICENSE、NOTICE、修改说明与第三方原文。不要推送私人开发检出的历史。
3. 启用仓库的私密漏洞报告入口。检查 SECURITY.md 的报告方式；确认其可用后再对外发布。Issue 模板禁止提交聊天、令牌和服务器地址。
4. 创建 v2.3.1-beta.2 的 Release 草稿，勾选 Pre-release。附上已核验的 Windows 安装包、完整源码包、校验清单和必要说明。
5. 从 GitHub 实际下载附件，再次核对校验值。确认来源、测试范围、未签名状态、手动更新和未接通功能均已说明后发布。

本地材料准备完成不等于 GitHub 已公开。账户、仓库地址、私密报告渠道和实际上传状态应以执行结果为准，不在文档中预先宣称完成。

Apache 2.0 允许符合条件的修改与衍生发行，修改文件须有显著修改声明并保留所需许可与来源通知；其他依赖仍按各自许可处理。本产品基于 AionUi / AionCore，不主张上游商标权或上游背书。小龙虾素材为 AI 辅助制作，来源记录随源码保留，不宣称全球独占版权。
