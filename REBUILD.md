# Rebuilding Xuzhou 2.3.1-beta.2 on Windows x64

Use Node.js 24, Bun 1.4.3, Rust/MSVC C++ Build Tools, CMake and NSIS 3.12. The pinned dependency locks and original license notices are included. Install tools into a location you control; no developer account, server login or private profile is needed.

1. Run the core recipe in build-tools/core against this source root. Keep the documented Windows migration checksums and independent PDF skill. New Core bytes require a fresh Core source/build review. Add --remap-path-prefix for your build directory if publishing newly compiled binaries.
2. Run bun install --frozen-lockfile in desktop and workbench. The desktop Node graph and the workbench runtime graph have separate locks. Build hooks for compiler dependencies may require explicit trust; do not enable scripts from unrelated packages.
3. Use resources/bundled-aioncore from the matching reviewed installer for the managed runtime assets. If rebuilding Core, replace its executable, update the manifest and independently review the new binary. Set XUZHOU_CORE_RESOURCES to that reviewed bundled-aioncore directory, then run node scripts/release/stageResources.cjs <source-root>. The script stages the bridge and pinned production dependencies and refuses to overwrite existing runtime trees. The hub is already included in this snapshot.
4. In desktop, run node scripts/generate-i18n-types.js, node scripts/check-i18n.js, type checking, focused and integration tests, then electron-vite build with packages/desktop/electron.vite.config.ts. Diagnostic telemetry and source-map upload are disabled by product policy.
5. Provide the checksum-verified Electron 44.8.0 Windows x64 distribution via XUZHOU_ELECTRON_DIST and the NSIS 3.12 bundle via XUZHOU_NSIS_ROOT. Set XUZHOU_BUILD_ROOT to this layout. Run node scripts/licensing/package.cjs <source-root> --prepare, then node scripts/release/reviewCandidate.cjs. Use a short junction to the exact unpacked payload via XUZHOU_NSIS_APP_DIR if your build path is long; package.cjs verifies that the junction resolves to that payload. Then invoke scripts/licensing/package.cjs.
6. A candidate policy permits packaging only. Independently verify the exact new installer, clean source archive, chat continuity, device controls, phone consent/revocation and original-data preservation before publishing. Never copy old final-approval JSON onto new bytes.

This source snapshot excludes all personal data, runtime binaries, node_modules, developer caches and local Git history. Dependencies must be rebuilt or fetched from their pinned sources. PUBLIC-FILES.json records every file in this clean tree, excluding itself.
